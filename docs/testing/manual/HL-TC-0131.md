# HL-TC-0131 — Zlecenie przyjęte przed aktualizacją pozostaje dostępne obok bieżącej misji

| Pole | Wartość |
|---|---|
| Typ | Ręczny odbiór i regresja v29 |
| Obszar | Zgodność zapisów |
| Priorytet | P0 |
| Stan definicji | READY |
| Wynik ręczny | **NOT RUN — nie wykonano** |
| Powiązane zmiany | [HL-CHG-1039](../../tracking/changes/HL-CHG-1039.md) |
| Środowisko | DEV 0.13.0.0/v29; wpisz rzeczywisty SHA/cache. PRE-PROD 0.12 nie zawiera automatycznie tej paczki. |

## Dane i warunki

Izolowany świat ze starym aktywnym zleceniem, wpłatą części zasobów, bieżącym rozdziałem Latarni i zapisem sprzed aktualizacji. Brak wymaganej fikstury, kontroli zegara lub usługi oznacza **BLOCKED**, nie PASS. Nie resetuj ani nie podmieniaj historii admin1–admin3.

## Kroki i oczekiwane wyniki

1. **Czynność:** Wczytaj zapis w nowym DEV i otwórz Aktualne Misje.

   **Oczekiwany wynik:** Bieżący etap głównej przygody jest jedynym odblokowanym etapem tej przygody. W osobnej sekcji widać już przyjęte wcześniej zlecenie z zachowanym terminem i wpłatami.

2. **Czynność:** Wpłać brakujące materiały i zakończ wcześniejsze zlecenie.

   **Oczekiwany wynik:** Zlecenie można dokończyć oraz otrzymać jego nagrodę jeden raz. Historia nie znika wskutek uporządkowania listy misji.

3. **Czynność:** Otwórz misje na nowym koncie po samouczku.

   **Oczekiwany wynik:** Nie pojawia się katalog nieprzyjętych dodatkowych zleceń wyglądających na równocześnie aktywne główne etapy.

## Raport wykonania

- Tester, data, rzeczywisty SHA/cache i środowisko: do uzupełnienia.
- Fikstura, język i rozmiar ekranu: do uzupełnienia.
- Wynik: **NOT RUN**; po wykonaniu PASS / FAIL / BLOCKED.
- Oczekiwane/uzyskane, dowód bez tokenów i numer błędu: do uzupełnienia.
