# HL-TC-0151 — Pomoc 5 i ratunek 3 odpowiadają na konkretny brak

| Pole | Wartość |
|---|---|
| Typ | Ręczny odbiór v31 |
| Obszar | Pomoc i ratunek |
| Priorytet | P0 |
| Stan definicji | READY |
| Wynik ręczny | **NOT RUN — nie wykonano** |
| Powiązane zmiany | [HL-CHG-1086](../../tracking/changes/HL-CHG-1086.md) |
| Środowisko | DEV 0.14.0.0 / v31 po integracji; wpisz rzeczywisty SHA i cache. PRE-PROD 0.13.1.0 nie zalicza tej próby. |

## Dane i warunki

Oddzielne kopie przerwanego etapu: brak zasobów, osób, miejsca i transportu.

Używaj izolowanego profilu QA i adaptera lub fikstury. Nie podmieniaj historii admin1–admin3. Brak właściwej implementacji, usługi lub danych oznacza **BLOCKED**, nie PASS.

## Kroki i oczekiwane wyniki

1. **Czynność:** Dopuść do niepowodzenia głównego etapu i otwórz pomoc.

   **Oczekiwany wynik:** Pięć etapów odnosi się do rzeczywistego braku oraz prowadzi do jego usunięcia.

2. **Czynność:** Przerwij pomoc, następnie wykonaj trzy etapy ratunku.

   **Oczekiwany wynik:** Wracasz do pomocy z poprawionym stanem. Nie dostajesz jedynie identycznego niedostępnego żądania.

3. **Czynność:** Dokończ pomoc i wróć do głównej historii.

   **Oczekiwany wynik:** Wcześniejsze etapy i wpłaty pozostają zaliczone. Kontynuowany jest właściwy następny etap.

## Raport wykonania

- Tester, data, rzeczywisty SHA/cache i środowisko: do uzupełnienia.
- Dane, założenia i ograniczenia: do uzupełnienia.
- Wynik: **NOT RUN**; po wykonaniu PASS / FAIL / BLOCKED.
- Oczekiwane/uzyskane, dowód bez tokenów i numer błędu: do uzupełnienia.
