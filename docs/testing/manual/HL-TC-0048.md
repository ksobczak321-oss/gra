# HL-TC-0048 — Prywatny czat1:1 nie ujawnia rozmów ani danych kont osobom trzecim

| Pole | Wartość |
|---|---|
| Typ | Ręczny przypadek testowy; nie zgłoszony incydent |
| Obszar | Prywatne wiadomości |
| Priorytet | P0 |
| Stan definicji | READY |
| Wynik ręczny | **NOT RUN — nie wykonano** |
| Powiązane zmiany | [HL-CHG-0931](../../tracking/changes/HL-CHG-0931.md) |
| Środowisko | Nowy zakres DEV po pilnej poprawce; nie zakłada wdrożenia PRE-PROD/PROD. |

## Dane i warunki

QA-DM: trzy syntetyczne kontaA/B/C, dwa konteksty przeglądarki i izolowany serwer społeczności. A i B mogą należeć do różnych sojuszy. C jest osobą obcą. Test nie wymaga e-maili ani prawdziwych danych. Jawny nietrwały DEVpreview nie dowodzi działania API GCP.

Konta `admin1`–`admin3` nie są jednorazowymi fixture. Nie resetuj i nie podmieniaj ich historii. Zapisz rzeczywisty build/SHA, adres/tryb DEV i dane QA. Brak potrzebnego fixture/usługi oznacza BLOCKED, nie PASS.

## Kroki i oczekiwane wyniki

1. **Czynność:** ZA rozpocznij prywatną rozmowę zB i wyślij tekst; odpowiedz zB. Otwórz osobno czat sojuszu.

   **Oczekiwany wynik:** Rozmowa1:1 i czat sojuszu są rozdzielone. Do rozmowy1:1 nie trzeba mieć wspólnego sojuszu. Nazwy publiczne nie ujawniają UID Firebase, e-maila i tokenów.

2. **Czynność:** ZC spróbuj pobrać i wysłać wiadomości przy znanym identyfikatorze cudzej rozmowy, także bezpośrednim żądaniem.

   **Oczekiwany wynik:** Serwer odrzuca dostęp osoby trzeciej do treści i listy wiadomości. Nie wystarcza ukrycie linku w interfejsie.

3. **Czynność:** Wyślij tekst podobny do HTML/skryptu, ponów identyczne żądanie po utracie odpowiedzi i spróbuj przekroczyć jawny limit wysyłki.

   **Oczekiwany wynik:** Tekst jest zwykłą treścią. To samo ID nie daje drugiej wiadomości. Limit jest egzekwowany serwerowo; klient nie udaje dostarczenia przy błędzie.

4. **Czynność:** ZablokujA zB, spróbuj nowej wiadomości i zgłoś istniejący wpis; sprawdź retencję w izolowanym zegarze serwera.

   **Oczekiwany wynik:** Blokada i zgłoszenie odnoszą się do konkretnego autora/wiadomości bez udostępniania cudzych rozmów. Stare sesje nie obchodzą blokady. Zwykłe wiadomości oraz zgłoszone fragmenty respektują zadeklarowane terminy retencji.

## Zakończenie

Zachowaj raport i dowody; usuń tylko izolowane dane QA. Nie uruchamiaj resetu właściciela ani operacji na prawdziwych płatnościach.

## Raport wykonania

- Tester i data: do uzupełnienia.
- Faktyczny build/SHA oraz środowisko: do uzupełnienia przed startem.
- Wynik: **NOT RUN**; po wykonaniu PASS / FAIL / BLOCKED.
- Fixture i dowód bez tokenów: do uzupełnienia.
- Odchylenia i numer zgłoszonego błędu: do uzupełnienia.
