# HL-TC-0157 — Opłacony plan uruchamia się po końcu pakietu

| Pole | Wartość |
|---|---|
| Typ | Ręczny odbiór v31 |
| Obszar | Planowanie |
| Priorytet | P0 |
| Stan definicji | READY |
| Wynik ręczny | **NOT RUN — nie wykonano** |
| Powiązane zmiany | [HL-CHG-1092](../../tracking/changes/HL-CHG-1092.md) |
| Środowisko | DEV 0.14.0.0 / v31 po integracji; wpisz rzeczywisty SHA i cache. PRE-PROD 0.13.1.0 nie zalicza tej próby. |

## Dane i warunki

Pakiet kończy się za 10 sekund; wymagane materiały napływają po jego końcu.

Używaj izolowanego profilu QA i adaptera lub fikstury. Nie podmieniaj historii admin1–admin3. Brak właściwej implementacji, usługi lub danych oznacza **BLOCKED**, nie PASS.

## Kroki i oczekiwane wyniki

1. **Czynność:** Zamów plan i odnotuj opłatę oraz warunki.

   **Oczekiwany wynik:** Cena jest pobrana raz, a plan pozostaje widoczny.

2. **Czynność:** Dopuść do wygaśnięcia pakietu, potem skompletuj koszt.

   **Oczekiwany wynik:** Plan rusza zgodnie z opłaconym uprawnieniem, bez żądania odnowienia pakietu.

3. **Czynność:** Sprawdź wznowienie oraz legalne anulowanie na osobnej kopii.

   **Oczekiwany wynik:** Potwierdzenia i rezerwacje są spójne; nie ma ponownej opłaty ani podwójnego zwrotu.

## Raport wykonania

- Tester, data, rzeczywisty SHA/cache i środowisko: do uzupełnienia.
- Dane, założenia i ograniczenia: do uzupełnienia.
- Wynik: **NOT RUN**; po wykonaniu PASS / FAIL / BLOCKED.
- Oczekiwane/uzyskane, dowód bez tokenów i numer błędu: do uzupełnienia.
