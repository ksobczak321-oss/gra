## Dane i warunki

QA-TRADE: trzy syntetyczne konta A/B/C z Ratuszem6; A ma100 drewna, B i C odpowiednią liczbę monet. Serwerowe API rynku działa na izolowanej bazie. Nowy kontrakt sprzedaje materiały za monety, a NPC działa równolegle. Jeżeli wymagane API nie jest dostępne, oznacz BLOCKED; dawny barter v22.1 jest tylko danymi migracyjnymi.

Brak przygotowanego, odizolowanego fixture lub brak dostępu do wskazanego trybu oznacza BLOCKED, a nie PASS.

Konta `admin1`–`admin3` nie są jednorazowymi fixture. Zgoda na osobny reset po promocji nie jest zgodą na dowolne resetowanie, manipulację zegarem lub podmianę ich danych podczas testów. Ten przypadek nie uruchamia skryptu resetu właściciela.

## Kroki i oczekiwane wyniki

1. **Czynność:** Sprawdź dostępność rynku graczy na TH5 i TH6; opublikuj z A ofertę100 drewna za40 monet (poniżej bazowej ceny NPC50).

   **Oczekiwany wynik:** OdTH6 działa rynek graczy obok NPC. Oferta podaje materiał, liczbę i cenę w monetach. A rezerwuje100 drewna raz; prywatny UID nie zastępuje publicznej nazwy. Stary formularz materiał–materiał nie tworzy nowej oferty.

2. **Czynność:** Spróbuj przyjąć tę samą ofertę równocześnie z B i drugim odrębnym kontem testowym albo powtórzyć to samo żądanie.

   **Oczekiwany wynik:** Tylko jedno przyjęcie skutkuje pobraniem monet i rozliczeniem towaru. Ponowienie nie daje drugich towarów/monet; nie można przyjąć własnej oferty ani wydać tych samych zarezerwowanych środków.

3. **Czynność:** Anuluj inną ofertę albo rozlicz jej wygaśnięcie przy pełnym magazynie właściciela.

   **Oczekiwany wynik:** Zwrot zachowuje materiały i bonusową ewidencję; niemieszcząca się część czeka w trwałej skrzynce. Sam GET listy nie pobiera ani nie oddaje środków. Wpływy ze sprzedaży są niekwalifikowane do dobroczynności. Cenę maksymalną i równoległe NPC sprawdza TC37.

Zamknij kontekst QA i usuń jego ulotny fixture. Nie zmieniaj rzeczywistych wysp ani konfiguracji chmury.
