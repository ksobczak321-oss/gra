## Dane i warunki

Użyj izolowanego profilu lub kontrolowanej fikstury z zapisanym Teatrem. Brak wymaganej usługi, kontroli zegara, odpowiedniego buildu lub fikstury oznacza **BLOCKED**, nie PASS. Nie resetuj ani nie podmieniaj historii admin1–admin3. Rzeczywistych płatności i reklam nie zastępuj fikcyjnym potwierdzeniem; w DEV używaj jawnej symulacji.

## Kroki i oczekiwane wyniki

1. **Czynność:** Sprawdź numer w Ustawieniach, rzeczywisty SHA i link do własnego CI nowej paczki.

   **Oczekiwany wynik:** Odbiór odnosi się do 0.13.1.0 i właściwego źródła; wyniki 0.13.0.0 nie są podawane jako test nowego kodu.

2. **Czynność:** Otwórz opublikowany podgląd po sukcesie jego Pages i przejdź z mapy do studia.

   **Oczekiwany wynik:** Pobrana wersja i grafika odpowiadają odebranemu źródłu. Sam push nie zastępuje wyniku workflow.

3. **Czynność:** Porównaj rejestr środowisk i zaznacz wyniki tylko rzeczywiście wykonanych prób.

   **Oczekiwany wynik:** PRE-PROD nadal ma wcześniejsze odebrane wydanie, bez niezamówionej promocji lub resetu. Tej definicji scenariusza nie oznaczono automatycznie PASS.

## Raport wykonania

- Tester, data, rzeczywisty SHA/cache i środowisko: do uzupełnienia.
- Fikstura, język i rozmiar ekranu: do uzupełnienia.
- Wynik: **NOT RUN**; po wykonaniu PASS / FAIL / BLOCKED.
- Oczekiwane/uzyskane, dowód bez tokenów i numer błędu: do uzupełnienia.
