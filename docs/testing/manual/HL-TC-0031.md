# HL-TC-0031 — Promocja zachowuje kolejność DEV → PRE-PROD → PROD

| Pole | Wartość |
|---|---|
| Typ | Ręczny przypadek testowy; nie zgłoszony incydent |
| Obszar | Wydanie |
| Priorytet | P0 |
| Stan definicji | READY |
| Wynik ręczny | **NOT RUN — nie wykonano** |
| Powiązane zmiany | [HL-CHG-0604](../../tracking/changes/HL-CHG-0604.md), [HL-CHG-0605](../../tracking/changes/HL-CHG-0605.md) |
| Środowisko | Odczyt dowodów wydania; bez jakichkolwiek mutacji GCP, domen, danych lubPROD. |
| Wersja odniesienia | PRE-PROD v22.1 / `092e75226fbb14cab09826f313e11d10891966d8`; nowe zakresy mają jawny status DEV/DRAFT |

## Dane i warunki

Odczyt publicznego/udostępnionego workflow oraz artefaktów; znany SHA aplikacji 092 e 75226 fbb 14 cab 09826 f 313 e 11 d 10891966 d 8, CI41221965032 i PRE-PROD41222765705. Nie uruchamiaj nowego wdrożenia ani PROD w ramach tego przypadku.

Brak przygotowanego, odizolowanego fixture lub brak dostępu do wskazanego trybu oznacza BLOCKED, a nie PASS.

Konta `admin1`–`admin3` nie są jednorazowymi fixture. Zgoda na osobny reset po promocji nie jest zgodą na dowolne resetowanie, manipulację zegarem lub podmianę ich danych podczas testów. Ten przypadek nie uruchamia skryptu resetu właściciela.

## Kroki i oczekiwane wyniki

1. **Czynność:** Porównaj SHA źródłowego CI, ręcznej promocji i manifestu publikacji albo potwierdzenia workflow.

   **Oczekiwany wynik:** Zielone CI i promocja dotyczą tego samego pełnegoSHA; push sam nie jest promocją GCP. Przy niedostępnym odczycie manifestu zapisujemy ograniczenie dowodu.

2. **Czynność:** Sprawdź nazwy obu artefaktów i próbę promocji.

   **Oczekiwany wynik:** Frontend i receipt pochodzą z tej samej udanej próby. HashZIP nie jest mylony z hashem tar.gz, manifestu ani digestem obrazu.

3. **Czynność:** Przejrzyj wymagania bramkiPROD bez jej uruchamiania.

   **Oczekiwany wynik:** Wymagane są sprawdzone artefakty PRE-PROD; aplikacja nie jest budowana na nowo dlaPROD. Sukces DEV tagu nie zastępuje weryfikacji receipt ani konfiguracji kont/API.

## Zakończenie

Zamknij odczyt. Nie usuwaj ani nie nadpisuj artefaktów.

## Raport wykonania

- Tester i data: do uzupełnienia.
- Faktyczny build/SHA oraz środowisko: do uzupełnienia przed startem.
- Wynik: **NOT RUN**; dozwolone po wykonaniu: PASS / FAIL / BLOCKED.
- Dowody: zrzuty ekranu, odpowiedzi/identyfikatory testowych żądań lub log harnessu, bez tokenów i prywatnych payloadów.
- Odchylenia i numer zgłoszonego błędu: do uzupełnienia; incydent powstaje dopiero po zaobserwowanej niezgodności.
