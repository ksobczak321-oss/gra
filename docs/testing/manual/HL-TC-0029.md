# HL-TC-0029 — „Zacznij od nowa” nie jest pełnym resetem trzech kont

| Pole | Wartość |
|---|---|
| Typ | Ręczny przypadek testowy; nie zgłoszony incydent |
| Obszar | Reset |
| Priorytet | P0 |
| Stan definicji | READY |
| Wynik ręczny | **NOT RUN — nie wykonano** |
| Powiązane zmiany | [HL-CHG-0413](../../tracking/changes/HL-CHG-0413.md), [HL-CHG-0414](../../tracking/changes/HL-CHG-0414.md) |
| Środowisko | DEV — lokalny harness i syntetyczne dane; opcjonalny PRE-PROD wyłącznie na wydzielonym profilu QA |
| Wersja odniesienia | PRE-PROD v22.1 / `092e75226fbb14cab09826f313e11d10891966d8`; nowe zakresy mają jawny status DEV/DRAFT |

## Dane i warunki

QA-RESET: jednorazowa kopia z jedną wyspą, ukończonymi lekcjami, testowym zakupem, historią lojalności/poleceń i znanym terminem welcome. Bez drugiej wyspy, ładunku, otwartych ofert ani nierozstrzygniętej mutacji. Właścicielski reset 3 profili wykonuje się oddzielnie, nigdy jako przygotowanie tego testu.

Brak przygotowanego, odizolowanego fixture lub brak dostępu do wskazanego trybu oznacza BLOCKED, a nie PASS.

Konta `admin1`–`admin3` nie są jednorazowymi fixture. Zgoda na osobny reset po promocji nie jest zgodą na dowolne resetowanie, manipulację zegarem lub podmianę ich danych podczas testów. Ten przypadek nie uruchamia skryptu resetu właściciela.

## Kroki i oczekiwane wyniki

1. **Czynność:** W ustawieniach wybierz „Rozpocznij nową wyspę” i przeczytaj potwierdzenie.

   **Oczekiwany wynik:** Opis mówi o utracie zasobów/wyspy oraz zachowaniu historii zakupów i jednorazowych uprawnień; nie obiecuje wyzerowania wszystkich kont.

2. **Czynność:** Potwierdź na jednorazowym koncie i poczekaj na zapis.

   **Oczekiwany wynik:** Zastąpiona zostaje tylko bieżąca pojedyncza wyspa, jej postęp i samouczek; pojawia się nowe wprowadzenie. Zachowane są commerce, loyalty, socialRewards, referrals, engagementSchedule, welcome, nazwa i ta sama generacja.

3. **Czynność:** W oddzielnej kopii z drugą wyspą lub aktywnym ładunkiem spróbuj tej opcji.

   **Oczekiwany wynik:** Przycisk jest zablokowany z wyjaśnieniem. Inne konto oraz jego wyspa pozostają nietknięte; nie przyjmujemy, że deklaracja kliknięcia przez użytkownika jest raportem PASS albo pełnym resetem `admin1`–`admin3`.

## Zakończenie

Usuń wyłącznie jednorazowy fixture. Nie stosuj przycisku na prawdziwym admin1 ani skryptu resetu właściciela do sprzątania testu.

## Raport wykonania

- Tester i data: do uzupełnienia.
- Faktyczny build/SHA oraz środowisko: do uzupełnienia przed startem.
- Wynik: **NOT RUN**; dozwolone po wykonaniu: PASS / FAIL / BLOCKED.
- Dowody: zrzuty ekranu, odpowiedzi/identyfikatory testowych żądań lub log harnessu, bez tokenów i prywatnych payloadów.
- Odchylenia i numer zgłoszonego błędu: do uzupełnienia; incydent powstaje dopiero po zaobserwowanej niezgodności.
